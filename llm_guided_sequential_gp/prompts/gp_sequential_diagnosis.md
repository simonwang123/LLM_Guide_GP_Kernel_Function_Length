# 序贯阶段：建议变量级长度尺度先验调整

## 本轮任务

当前模型 M_t 使用前 t 个已揭晓的有限元样本训练，并在第 t+1 个设计的真值揭晓前封存了预测。现在该点的真值已经揭晓。请结合截至本步更新的统计摘要、封存预测误差和当前模型状态，判断下一次训练是否值得尝试改变一个或多个响应—变量关系的长度尺度先验类别。

你可以保持现有类别，也可以提出最多三个候选调整。每项调整指定一个响应和一个变量；多项调整可以涉及同一响应的不同变量，也可以涉及不同响应。程序会将本步新样本加入训练集，比较不调整、单项调整及多项联合调整后的模型；经验证后可以同时采纳多项调整。你的建议本身不代表模型已经改善。即使保持类别，程序也会用新样本重新训练。

## 本轮输入

下方 JSON 由诊断脚本生成：

- `sample_index` 和 `design_id` 标识刚揭晓的样本；`training_sample_count` 是揭晓前用于训练 M_t 的样本数，应比 `sample_index` 少 1。
- `statistics` 使用包含本步新点的全部已揭晓样本，按八个变量行、三个响应列给出偏 Spearman 系数和单变量二次拟合的留一预测 R² 增益。null 表示该统计量无法计算；输入不包含逐样本坐标或响应历史。
- `responses` 按响应给出本步真值、封存的预测均值和预测标准差、预测误差，以及 `fitted_length_scales_unit_space`。其中 `lengthscale_prior_categories` 才是当前生效的 short、base、long 类别；拟合出的长度尺度是当前数据和先验共同作用的结果，两者不能混为一谈。若 `sigma_floor_applied` 为 true，标准化误差使用了数值保护，解释该数值时要谨慎。
- `coverage` 描述新点相对旧训练设计的距离。每个响应的 `taylor_attribution` 在新点处计算 M_t 的预测均值梯度，分别乘以三个欧氏最近邻到新点的八维差值；按三点绝对贡献均值给出 Top-3 和占比。`direction_counts` 反映三点贡献方向。`approximation_checks` 对照一阶和实际 GP 预测增量；若 `poor_approximation` 为 true，不宜过度解读排序。这些值解释模型预测变化，不是观测残差的因果分解。`issue_class` 只是误差筛查标签。
- `engineering_prior` 中的 `prior_sign` 和 `prior_tier` 给出原有工程知识的方向与强度。矩阵按八个变量为行、三个响应为列；这些信息不直接表示变化快慢。`recent_interventions` 仅记录实际提供的近期干预；若 `recent_interventions_status` 为 `not_provided`，不能推断此前没有干预。

## 判断方法

1. 核对当前模型的 `current_model.lengthscale_rule_mode` 是否为 `soft_log_normal`，以及三个响应是否各有八个当前先验类别。若仍为旧硬下界模式、当前类别缺失，或样本身份与关键数值互相矛盾，返回 `INVALID_INPUT` 并指出问题。证据不足以提出调整属于正常情况，应选择 `KEEP`。
2. 分别考察三个响应。结合更新后的两组统计量、本步预测误差、Top-3 排查候选、当前先验类别、拟合长度尺度和工程依据，判断是否存在值得测试的“变化更快”或“变化更平缓”的假设。没有逐样本历史输入，不要声称核对过具体历史点。单点大误差、单个拟合长度尺度或泰勒贡献排名都不能独自证明调整有效。
3. 有具体依据时，可以提出 short、base、long 中任何与当前类别不同的类别。候选不要求达到固定的标准化误差或近邻距离门槛；但每项理由必须说明为什么选中这个响应和变量，并交代多变量变化及一阶近似的局限。若无法指出可信的响应—变量关系，保持当前类别。
4. 每项调整都从本轮当前类别出发，不重复修改同一个响应—变量组合。提出多项调整时，在整体理由中说明它们为什么值得一起检验。单项调整的效果不能直接代表联合调整的效果；只描述待检验的模型假设，不填写未经验证的精度提升数字，也不要声称留一验证已经通过。

## 输出格式

只输出一个合法 JSON 对象，不附加代码围栏或说明文字。顶层恰好包含以下八个字段：

- `schema_version`：整数 `2`。
- `status`：正常判断为 `"OK"`；关键输入无法用于判断时为 `"INVALID_INPUT"`。
- `sample_index`、`design_id`：照录本轮输入中的整数样本编号和设计编号，不得省略或改写。
- `decision`：`status="OK"` 时为 `"KEEP"` 或 `"MODIFY"`；输入无效时为 `null`。`MODIFY` 表示提出待验证的调整，不表示程序已采纳。
- `candidates`：`KEEP` 或输入无效时为空数组；`MODIFY` 时为一至三个调整对象。数组中的调整可以同时应用，并须作为联合方案接受验证。每个对象恰好包含 `response`、`variable`、`from_category`、`to_category`、`reason` 五个字符串字段。
  - `response` 和 `variable` 必须是输入中已有的响应名和变量名。
  - `from_category` 必须等于该响应—变量当前的 `lengthscale_prior_categories` 值；`to_category` 必须是与当前类别不同的 `"short"`、`"base"` 或 `"long"`。
  - 不得重复同一个响应—变量组合。每条 `reason` 用完整句子写明可见的观测或工程依据，以及主要不确定性。
- `reason`：正常判断时为非空字符串，概括本轮三个响应的主要证据，以及为何保持现状或提出这些调整；提出多项时还须说明联合检验的理由。输入无效时为 `null`。
- `error`：正常判断时为 `null`；输入无效时为指出具体字段或矛盾的非空字符串。

输出前核对：`KEEP` 对应零项调整，`MODIFY` 对应一至三项可联合检验的调整；类别取值和当前类别一致性正确；理由没有把预测误差或多变量联合变化写成单变量因果证明。
